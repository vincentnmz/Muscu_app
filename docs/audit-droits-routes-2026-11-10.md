# Audit P2.1 — droits d'accès route par route (10/11/2026)

> Plan d'audit : `docs/audit-architecture-2026-11-09.md` (P2, 1er point). **Aucune modification du code de l'app ni de la base de prod.**
> Légende de preuve : **[V]** vérifié (code + appel réel mesuré) · **[D]** déduction · **[?]** inconnu.

## Méthode

- **Routes** : extraites automatiquement du routeur réel d'`index.ts` (`scripts/audit-droits/extraire.mjs`) — **121 entrées de routage** (20 GET, 101 POST) = **118 actions distinctes** (`login`, `register`, `loginCoach` existent en GET et en POST). Pour chaque route : les clés réellement lues par son traitement (`body.x`, `params.get('x')`).
- **Banc** (`scripts/audit-droits/audit.js`) : le VRAI `index.ts`, `AUTH_ENFORCE=1`, sessions signées réelles, **base neuve à chaque appel**. Données « à protéger » marquées `SECRET_A2` (athlète A2 / coach C2) et `SECRET_A3` (athlète sans coach). Pour chaque appel on **mesure** : statut HTTP, **fuite** (marqueur dans la réponse, dans un e-mail ou push sortant, ou lien signé vers un fichier de A2), **modification** (ligne de A2 / C2 changée, supprimée ou ajoutée, fichier supprimé), erreur serveur.
- **Scénarios** (jusqu'à 10 par route, **919 appels** au total) : sans jeton · athlète A → données de B · coach → athlète hors périmètre · ID manipulé (son athlete_id + ressource de B) · ressource seule (identité retirée) · athlète → route coach · coach → route athlète (son athlète) · propriétaire légitime (contrôle positif) · ID inexistant.
- **Validité du banc** vérifiée : les **103 routes protégées acceptent leur propriétaire légitime** (sinon un refus ne prouverait rien) ; aucune erreur serveur ; deux artefacts du banc corrigés en cours (limite de débit 60 req/min/IP qui masquait 762 appels ; cache de révocation de session) — détail en fin de document.
- **Confirmation réelle** du cas 🔴 sur la **préprod** (serveur réel, 2 messages de test insérés puis supprimés).

## Résultat en une phrase

Le contrôle d'accès est **effectif sur toutes les routes qui reçoivent un identifiant** (athlete_id, coach_id, ligne, chemin) : sans jeton = 401 partout, athlète A → B refusé partout, coach hors périmètre refusé partout. **Mais il existe 1 faille 🔴** : une route qui, **sans identifiant**, ne filtre plus rien.

## 🔴 C1 — `getCommentaires` : lecture de TOUS les messages par n'importe quel athlète connecté [V]

- **Constat (code)** : `handleGetCommentaires` filtre sur `coach_id` / `athlete_id` **seulement s'ils sont fournis**. `authCheck` ne contrôle que les identifiants **présents** : un athlète qui n'en envoie aucun passe, et la requête lit toute la table `commentaires` (+ liens signés de lecture de tous les médias photo / vidéo).
- **Preuve** : banc (scénario « ressource seule ») → messages de A2 et A3 renvoyés à A1. **Préprod réelle** : John (athlète) sans identifiant → reçoit le message **privé de Lucas** (2 messages / 2 athlètes) ; avec son `athlete_id` → seulement le sien.
- **Exploitable par** : toute personne qui crée un compte athlète (inscription publique) — une seule URL. Le code en prod (v246) est identique au dépôt **[V]** → **la faille existe en prod**, sur les vrais messages coach ↔ testeurs. **[D]** pas de trace d'exploitation recherchée (logs non analysés).
- **Côté coach** : non concerné (`authCheck` impose `coach_id` = session).
- **Impact d'une correction sur l'app** : toutes les lectures de l'app (6 appels dans `js/app.js`) envoient déjà `athlete_id` **[V]** → imposer / exiger l'identifiant pour une session athlète ne change rien pour l'app.
- **✅ CORRIGÉ (10/11)** — commit `68d5b29`, préprod puis **prod v247** (smoke test prod : John→John 200, John sans id 200 uniquement ses fils, John→Lucas 401, `athlete_id=null` 401, sans jeton 401, logs sans erreur). Test permanent `tests/securite-getcommentaires.test.js` (19/19 ; 7 KO sur l'ancien code).
- **Correction (appliquée)** : dans `authCheck` (ou le traitement), pour `getCommentaires` en session athlète : `athlete_id` absent → forcé à l'id de la session (comme déjà fait pour le coach avec `coach_id`). Test de non-régression associé.

- Routes protégées **sans test dédié** dans `tests/` : contrôle vérifié ici, mais aucun test permanent — voir colonne « Test existant ».

## Limites

- **Base simulée** pour le banc (le vrai Postgres n'est pas en jeu : RLS est fermé et seul le serveur accède à la base, donc c'est bien `index.ts` qu'il faut tester). Confirmation réelle faite seulement pour 🔴.
- **Charges utiles générées** à partir des clés lues par chaque traitement : une route peut avoir un chemin interne non atteint (ex. `claimRecompense` testée avec une récompense indisponible). **[D]**
- **Effets de bord** mesurés : base, stockage, e-mails / push sortants. Pas mesuré : coût (IA), journaux.
- **Artefacts corrigés pendant l'audit** : (1) limite de débit 60 req/min/IP → une IP par appel ; (2) cache de 30 s de révocation de session → vidé entre appels ; (3) `ilike` absent de la base simulée ; (4) lignes `objectif` sans `id` dans la base simulée (faux positif sur `saveObjectif`).
- Rejouer : `node scripts/audit-droits/extraire.mjs && node scripts/audit-droits/audit.js && node scripts/audit-droits/matrice.js`.
